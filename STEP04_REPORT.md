## 1. Executive Summary

STEP 04 resolves the core reliability bottleneck reported in FACECORE AI where uploaded images exhibited a fundamental contradiction between diagnostics and comparison:
- **Reported Bug:** Some pairs of uploaded images failed during comparison with `Multiple faces (2 detected) in Image A (Probe)`, while the image diagnostics panel displayed `0 Faces Detected`.
- **Targeted Outcome:** Unified face detection across validation and comparison, interactive user-controlled multi-face selection, manual crop recovery for undetected faces, quality advisory warnings, and comprehensive regression coverage across 12 criteria without altering SFace weights, embedding mathematics, or ephemeral privacy guarantees.

### Key Architectural Deliverables:
1. **Shared Detection Architecture:** Created a single unified [`SharedFaceDetector`](file:///c:/Projects/project%207%20-%20face%20checking%20tool/backend/app/services/face_detector.py) wrapping OpenCV YuNet (`cv2.FaceDetectorYN`). Diagnostics (`/api/validate-image`) and comparison (`/api/compare`) now share the exact same detection engine, image preprocessing, and structured candidate filtering.
2. **False-Positive Filtering:** Implemented geometric and confidence checks (`is_plausible_face_candidate`) that reject sliver bounding boxes, degenerate dimensions ($<16\times 16$), collapsed landmark geometry ($<4$ px inter-pupillary distance), and low-confidence detector noise.
3. **Multi-Face User Experience:** When multiple faces are detected, the workflow does **not** abort. The UI overlays numbered reticles on the image with confidence readouts, displays a multi-face selector bar, and allows the operator to select the active target face before triggering comparison.
4. **No-Face Manual Crop Recovery:** When 0 faces are detected, the system fails validation honestly (`passes_quality_check = False`, `No Face Localized`) and presents an interactive drag-to-crop modal (`ManualCropModal`). The crop is strictly validated through YuNet before embedding generation.
5. **Absolute Diagnostics Consistency:** Diagnostics display the exact face count, confidence, and bounding box coordinates generated by the shared detector, making it impossible for the diagnostics panel to disagree with the comparison engine.
6. **Zero Score Fabrication:** No arbitrary similarity scores or background embeddings are generated. When face localization fails or crops contain no human face, clear domain errors (`NoFaceDetectedError`, `InvalidFaceSelectionError`) are returned with actionable recovery guidance.

## 2. Root Cause Audit & Reproduction

### Root Cause Analysis
An inspection of `backend/app/services/image_validator.py` and `backend/app/engine/real_engine.py` revealed the exact origin of the reported discrepancy:

| Pipeline Component | Endpoint | Implementation Prior to Step 04 | Face Detection Behavior |
| :--- | :--- | :--- | :--- |
| **Diagnostics Panel** | `/api/validate-image` | Invoked `validate_image_bytes()` which used **only Pillow** (`PIL.Image`) for dimensions, color mode, Laplacian variance, and brightness. | **YuNet was NEVER called.** In `schemas.py`, `face_detected` defaulted to `False` and `face_count` defaulted to `0`. Diagnostics rendered `"0 Faces Detected"` for **every** uploaded image. |
| **Comparison Pipeline** | `/api/compare` | Invoked `active_engine.compare_faces()`, which instantiated YuNet (`cv2.FaceDetectorYN`) directly inside `detect_and_extract_face()`. | YuNet executed correctly and detected both genuine faces. When `len(faces) > 1`, `real_engine.py` raised `MultipleFacesDetectedError("Multiple faces (2 detected) in Image A (Probe)...")`. |

### Consequence:
When a user uploaded a group or dual-face image, `/api/validate-image` returned `face_count = 0` (causing diagnostics to say `"0 Faces Detected"`), but `/api/compare` executed YuNet and aborted with `"Multiple faces (2 detected)"`. The user saw a direct contradiction between the diagnostics panel and the comparison error banner.

### Verification & Reproduction:
Prior to changing code, synthetic two-face images were submitted to both endpoints. The diagnostics endpoint responded with `face_count: 0`, while the compare endpoint threw `MultipleFacesDetectedError`. Step 04 unifies both endpoints around a single detector service.

### Color Conversion & Preprocessing Invariance
- OpenCV YuNet requires standard BGR images. Previously, inconsistent PIL RGB conversion versus OpenCV BGR decoding created alignment drift.
- `SharedFaceDetector` reads raw bytes directly via `cv2.imdecode(np.frombuffer(raw_bytes, np.uint8), cv2.IMREAD_COLOR)` ensuring strict BGR compatibility with YuNet.
- When generating SFace embeddings, the aligned 112x112 crop produced by `cv2.FaceRecognizerSF.alignCrop` is utilized directly, matching the exact OpenCV SFace C++ specification.

### Dual-Mode Crop Recovery Logic
When a user draws a crop box $[cx, cy, cw, ch]$:
1. **Mode A (Spatial Containment):** If full-image detection already localized faces, any face whose center $(fx + fw/2, fy + fh/2)$ falls within $[cx, cy, cx+cw, cy+ch]$ is selected and coordinate-shifted to the crop reference frame.
2. **Mode B (Sub-Image Re-Detection):** If no face was found on the full canvas (e.g., small face in a large image or peripheral subject), the sub-image is sliced: `sub_img = bgr_img[cy:cy+ch, cx:cx+cw]`. YuNet is dynamically resized to `(cw, ch)` and re-executed strictly within the sub-image. Coordinates are mapped back to the full image.
3. **Anti-Fabrication Guard:** If YuNet detects 0 faces inside the crop, validation fails immediately. **Embeddings are never extracted from arbitrary non-face backgrounds.**

## 8. Remaining Limitations & Operating Guidance

1. **Extreme Profile Views ($> 60^\circ$ Yaw):** YuNet's 5-point landmark regressor requires both eyes and at least one mouth corner to be visible. Faces oriented in extreme profile ($> 60^\circ$) may not achieve landmark convergence. Operators are prompted to utilize the Manual Face Crop tool or supply a frontal/semi-frontal photograph.
2. **Heavy Facial Occlusion ($> 70\%$ Covered):** Substantial occlusions (e.g., ski masks, dense scarfs, full-face coverings) prevent landmark localization. The detector rejects such regions to prevent arbitrary vector generation.
3. **Severe Blur ($< 10$ Laplacian Variance):** While YuNet can occasionally localize heavily motion-blurred faces, SFace's 128-d cosine representation degrades significantly on unsharp imagery. The quality diagnostics panel flags these as `High Motion Blur Detected` advisory warnings.
4. **Minimum Crop Resolution ($< 32\times 32$ px):** Manual crops must enclose at least $32 \times 32$ pixels to ensure sufficient facial feature resolution for neural inference.
